## Phase 0 — Technical Spike ⬜

写代码前先验证三个最高风险点（PRD §19）：

- [x] **Spike A（macOS）**：选目录 → Security-Scoped Access → Rename → Undo 完整走通 ✅（2026-09-03）

  **结论**：链路全部可行。`fileImporter` 选目录 + `startAccessingSecurityScopedResource` 可获得写权限；security-scoped bookmark 存 UserDefaults 后重启可恢复访问；沙盒内重命名与撤销正常；目标重名时拒绝执行（Never Overwrite）。扩展名按产品语义（PRD F-06）由 UI 层保留，模板只生成基础名。已产出的可复用代码：`RenameRecord` / `RenameJournal` / `RenameEngine`（10 个单元测试覆盖）。
- [x] **Spike B**：读取常见格式 EXIF（JPG / HEIC / ARW / CR3 / NEF / RAF）🟨（2026-09-03，JPEG/HEIC 已验证，RAW 待真实样本）

  **结论**：`CGImageSourceCopyPropertiesAtIndex` 对 JPEG / HEIC 可稳定读出 DateTimeOriginal / Make / Model / LensModel（已用 ImageIO 生成的含 EXIF 夹具固化成 4 个单元测试）。**RAW 格式无法伪造样本**，ARW/CR3/NEF/RAF 待拿到真实拍摄文件后补验——这是 Phase 2 前必须补上的验证点。夹具生成脚本：`../test/generate_fixtures.swift`。已产出：`PhotoMetadata` / `MetadataReader`。**已知限制**：EXIF 时间不含时区，目前按本机时区解释；真实场景（跨时区拍摄、DST）需要专门设计，实现 Phase 2 时处理。
- [x] **Spike C**：RAW + JPEG + XMP 的 Asset Grouping 配对规则验证 ✅（2026-09-03）

  **结论**：配对规则确定为「同一目录 + 文件名基础名（大小写不敏感）」，独立文件自成一组，输出按基础名稳定排序。无需真实文件即可验证（纯逻辑）。已产出：`ResourceKind(fileExtension:)` 分类（覆盖 PRD F-02 全部格式）+ `AssetGrouper`。Phase 2 需补充：跨目录扫描时的按目录分组、同 stem 多 RAW 的冲突处理。

## Phase 4 — Preflight 🟨（MVP 的核心能力）

F-09 检查项：Filename Conflict（目标已存在）、Duplicate Name（批内撞名）、Duplicate Timestamp（连拍同秒，用 Sequence 消解）、Missing Sidecar、Invalid Filename（跨文件系统非法字符）、Missing EXIF、Permission。

**已实现（2026-09-04）**：`PreflightEngine` 在生成预览时同步运行，报告分两级——阻塞级（目标已存在 / 批内重复 / 非法文件名含子目录逃逸 / 目录不可写）禁止执行；警告级（缺拍摄时间 / 缺 XMP sidecar）提示后允许继续。UI 预览区直接显示问题清单，红色阻塞 / 橙色警告。

**待做**：Duplicate Timestamp 的 Sequence 消解策略（当前靠 {index} 天然避免）。

**F-05 拍摄时间 fallback 链已实现（2026-09-04，原属 Phase 2/4 缺口）**：`CaptureTimeResolver` 按 EXIF → Media Creation Date（Spotlight，未索引卷自动跳过）→ 文件创建日期 → 文件修改日期取时间；`PhotoMetadata.captureTimeSource` 记录实际来源，预检对非 EXIF 来源发橙色警告（含来源与数量），完全无时间才报缺时间警告。深层回退顺序用注入 provider 的方式固化成测试（真实文件系统造不出"无创建日期"的文件）。

## Phase 5 — Rename Transaction ✅（**全项目技术核心**）

- F-10 事务化重命名：可恢复、可检测部分失败、避免名称交换冲突、绝不覆盖
- F-11 Operation Journal：本地日志（Transaction / Timestamp / Source Folder / 原路径 / 新路径 / Status）
- F-12 Undo：Asset Group 整体撤销；Journal 支撑 Undo + Crash Recovery

**撤销粒度设计（2026-09-04 与产品对齐后确定）**：

| 级别 | 单位 | 说明 |
|------|------|------|
| 批次级 ✅ 已实现 | 一次批量执行（Transaction） | 主按钮「撤销上一批」，整体回退 |
| 资产级 ✅ 已实现 | 一个 PhotoAsset 整组 | 侧栏右键「撤销此资产的最近变更」 |
| ~~文件级~~ ✗ 不做 | 单个文件 | 会造成组内半改状态（RAW 旧名 + JPG 新名），违反 Asset Atomicity |

**跨批次规则**：撤销只能按批次逆序进行，不能跳批（第 1 批 A→X、第 2 批 X→Y 时，只撤第 1 批会把文件拖到从未存在过的状态）。Journal 中每条记录带 `transactionID` + `assetID`；无 ID 的旧格式记录自动按单条事务兼容。

**Crash Recovery 已实现（2026-09-10，Phase 5 收尾）**：批量执行前把完整意图清单原子写入活动标记文件（`ActiveTransactionStore`），全部成功后清除——Journal 64 条缓冲的崩溃丢记录窗口由标记兜底。启动检测到标记时用 `RecoveryEngine.reconcile` 对照磁盘调和：目标存在→已完成、源存在→未执行、源目标同时存在或同时缺失→冲突（绝不自动处理）；UI 橙色横幅引导「回退已改名文件（逆序 + Never Overwrite）/ 忽略」。另有恒等操作过滤：已按模板命名过的目录再次预览不再误报冲突（踩坑记录 #3）。

## Phase 6 — UI 🟨

macOS 三栏结构（PRD §11）：Sources / Assets / Inspector + 底部 Template → Preview → Preflight → Rename 工作流。iPadOS 为现场工作流定位（SD 读卡器 → iPad → 移动 SSD）。

**已实现雏形（2026-09-04，`AssetBrowserView`）**：三栏 NavigationSplitView——侧栏（选文件夹 + 来源统计）/ 资产列表（选中 + 改名预览组 + 资产右键撤销）/ Inspector（选中资产的拍摄时间/机身/镜头/资源及新名预览，未选中时显示摘要与预检结果）/ 底部工作流条（模板 + 项目名 + 撤销/预览/执行 + 预检问题摘要）。

**执行进度设计（2026-09-04 补充，PRD 未定义）**：PRD §11/F-10 没有进度相关设计，此为本项目补充——三个重 I/O 阶段都必须有进度反馈：读元数据（x/total，已实现）、预检（状态提示，已实现）、执行重命名（x/total，已实现）；执行期间 `isBusy` 禁用全部操作按钮。Journal 落盘按 64 条缓冲批量写（修复 3000 文件 = 3000 次全量重写 JSON 的 O(n²) I/O），崩溃丢记录的窗口已由活动标记兜底（见 Phase 5 Crash Recovery）。待精修：空态、大列表渲染、预览表排序筛选（Preset 选择器与实时预览已完成 2026-09-08）。

## 商业模式（以 [产品商业化文档](../20-产品PRD/产品商业化文档.md) 为准）

- **Free**：完整安全流程可用（Scan / EXIF / Asset Group / 排序 / 内置模板 / Preview / Preflight / Rename / Undo），单批限 50–100 Assets —— **安全功能永不收费**（§8）
- **Pro Lifetime**：Non-Consumable 买断，Product ID `com.photoname.pro`，初始价 $9.99，随阶段涨至 $14.99 / $19.99+，**涨价不影响老用户**（§18-19）
- **无账号、无登录、无自建服务器、无 License Key、无订阅**（§40-41）
- Entitlement 的 Source of Truth 是 StoreKit Transaction，本地缓存仅用于快速启动（§28）；Refund/Revocation 后需重算 isPro（§31）

### ⚠️ 代码改造点

`EntitlementManager.swift` 目前基于**订阅 API**（`Product.SubscriptionInfo.RenewalState`）设计，已确认改为**买断制（Non-Consumable）**，实现 C1 时需重构：从 `Transaction.currentEntitlements` 中匹配 `com.photoname.pro` 产品。另外商业化文档 §21-25 要求的分层中，`PurchaseManager`（StoreKit 唯一入口）尚不存在，需在 `Commerce/Store/` 下新建。

## 关键设计约束

- **Safe First**：Never Overwrite / Preview Before Mutation / Asset 原子性（RAW+JPEG+XMP 要么全成功要么全失败）/ 可恢复 / 显式告警（PRD §12）
- **Local First**：照片、EXIF、GPS 不上传；不要求登录；理想情况下不引入第三方 Analytics SDK（PRD §13）
- **Sandbox**：文件访问走 `user-selected.read-write` + security-scoped bookmark
- **UI 只是 Core 能力的展示层**（PRD §18），双平台共享 Core
