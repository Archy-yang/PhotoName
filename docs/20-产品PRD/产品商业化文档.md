# PhotoName — 商业化与收费策略设计

> **文档类型：** 商业化 / 授权 / StoreKit 设计基线
> **项目：** PhotoName
> **产品模式：** Local First / 无自建服务器 / 一次性买断为主
> **状态：** 初始规划
> **适用范围：** macOS / iPadOS / 后续 iOS

---

# 1. 文档目标

本文档用于定义 PhotoName 的商业化策略以及收费模块的技术设计原则。

后续开发过程中，涉及以下问题时，应优先参考本文档：

* 免费版与 Pro 版如何划分；
* 哪些功能可以收费；
* 哪些安全功能必须免费；
* 是否需要用户账号；
* 是否需要自建授权服务器；
* 如何通过 App Store 完成购买；
* 如何判断用户是否拥有 Pro；
* 如何恢复购买；
* 产品涨价后如何处理老用户；
* 后续新增大型功能时如何收费；
* StoreKit 模块应该如何与业务代码解耦。

核心目标是：

> **在不建设任何自有服务器的前提下，建立简单、稳定、可持续演进的 PhotoName 商业化体系。**

---

# 2. 商业化核心原则

PhotoName 的商业化设计遵循以下原则。

## 2.1 不建设自有服务器

PhotoName 不因为付费功能而引入：

* 用户系统；
* 登录系统；
* License Server；
* 自建购买验证服务器；
* 用户数据库；
* Token / JWT；
* 云端授权状态；
* 订阅服务后台。

用户购买身份与购买记录由 Apple App Store 管理。

PhotoName 只通过 StoreKit 获取用户当前拥有的购买权益。

整体结构：

```text
Apple Account
      ↓
   App Store
      ↓
   StoreKit
      ↓
PurchaseManager
      ↓
EntitlementManager
      ↓
  PhotoName
```

PhotoName 无需知道：

> “这个用户是谁。”

只需要知道：

> “当前 Apple Account 是否拥有 PhotoName Pro。”

---

# 3. Local First 与联网边界

PhotoName 是一个纯本地摄影工具。

以下内容必须完全本地完成：

```text
照片读取
EXIF 读取
RAW / JPEG / XMP 识别
Asset Grouping
排序
Template 处理
Preflight
Rename
Transaction
Journal
Undo
Recovery
```

照片、EXIF、GPS 等用户摄影数据：

> **不得为了核心功能上传至 PhotoName 自建服务。**

---

## 3.1 什么情况下允许联网

PhotoName 自身不依赖服务器。

但以下 Apple 系统能力可能需要联网：

### App Store 购买

用户购买 PhotoName Pro 时：

```text
PhotoName
    ↓
StoreKit
    ↓
App Store
```

---

### Restore Purchase

用户换 Mac / iPad 后恢复购买：

```text
Install PhotoName
      ↓
StoreKit
      ↓
Apple Account
      ↓
Restore Pro
```

---

### App Store 更新

由 Apple 管理。

---

因此产品宣传中应区分：

> **Photo processing is 100% local.**

而不要宣称：

> App 永远不会产生任何网络连接。

只保留两个主要授权状态：

```text

```

# 5. Pro 的购买类型

在 App Store Connect 创建：

```text
Product ID

com.photoname.pro
```

具体 ID 可以根据正式 Bundle ID 调整。

类型：

> **Non-Consumable In-App Purchase**

即：

> 用户购买一次，永久拥有。

PhotoName 第一阶段不采用订阅。

---

# 6. 为什么不做订阅

PhotoName 本质上是：

> Buy once, use when needed

类型的软件。

用户可能：

```text
周末拍摄
↓
使用 PhotoName

一周不用

旅行
↓
再次使用 PhotoName
```

它不是持续提供：

* 云存储；
* 在线 AI；
* SaaS；
* Server Processing；
* 持续内容服务；

因此当前没有足够合理的订阅理由。

强行采用订阅可能降低目标摄影用户的购买意愿。

所以第一阶段原则：

> **Lifetime Purchase First。**

---

# 7. 免费版设计原则

免费版的目的不是“尽可能限制用户”。

而是：

> **让用户真正体验一次完整、安全的 PhotoName Workflow。**

用户应该能够通过免费版验证：

* PhotoName 能不能正确识别自己的照片；
* RAW / JPEG / XMP 是否正确成组；
* EXIF 是否正确；
* Template 是否符合预期；
* Preview 是否准确；
* Preflight 是否可靠；
* Rename 是否安全；
* Undo 是否有效。

只有亲自完成这套流程，用户才有可能建立信任。

---

# 8. Safety Features 永远不能作为收费墙

PhotoName 的核心定位是：

> Safe Photo Renamer

所以任何直接与数据安全相关的功能：

> **不得因为用户没有购买 Pro 而关闭。**

以下能力 Free 和 Pro 都必须拥有：

```text
Preview

Preflight

Filename Conflict Detection

Duplicate Detection

Permission Check

Invalid Filename Detection

No Overwrite

Transactional Rename

Operation Journal

Undo

Crash Recovery
```

不能设计成：

```text
Free
没有 Undo

Pro
才有 Undo
```

也不能：

```text
Free
没有 Conflict Detection

Pro
才检查冲突
```

因为：

> 安全不是高级功能，而是 PhotoName 的产品底线。

---

# 9. Free 应该限制什么

免费版主要限制：

> **规模与效率。**

而不是安全性。

建议第一版：

## PhotoName Free

支持：

```text
✓ Directory Scan

✓ EXIF Metadata

✓ RAW / JPEG / XMP Asset Group

✓ Capture Time Sorting

✓ Built-in Templates

✓ Preview

✓ Preflight

✓ Transactional Rename

✓ Undo
```

限制：

```text
每次最多处理 50 ~ 100 个 Photo Assets
```

以及：

```text
只能使用若干内置 Template
```

具体数量上线前再通过产品体验确定。

---

# 10. Pro 提供什么

## PhotoName Pro

解除规模限制：

```text
Unlimited Assets
```

支持：

```text
Unlimited Rename
```

以及高级效率能力：

```text
Custom Templates

Unlimited Templates

Advanced Template Variables

Custom Project Name

Advanced Sequence Rules
```

未来所有专业工作流功能默认属于 Pro：

```text
Multi-Camera Timeline

Advanced RAW Workflow

Advanced Sidecar Management

Batch Ingest

Folder Templates

Backup Workflow

Checksum Verification
```

PhotoName 不应该刚打开就频繁展示购买页。

最自然的收费节点是：

用户已经完成：

```text

↓
Asset Group
↓

↓

↓
Preflight
```

此时 PhotoName 告诉用户：

```text

Unlock PhotoName Pro
Lifetime Purchase
```

这时用户已经看到：

> PhotoName 确实可以正确处理自己的素材。

购买决定会更自然。

# 12. 不建议采用的收费方式

## 12.1 不做功能碎片化收费

不建议建立：

```text
RAW Pack           $2.99

XMP Pack           $2.99

SD Card Pack       $2.99

Multi-Camera       $4.99

Backup Pack        $4.99

Advanced Template  $2.99
```

虽然 StoreKit 技术上支持，但会造成：

> 每用一个功能都需要再次付费。

用户体验会非常差。

PhotoName 第一阶段应该保持：

```text
Free
↓
Pro
```

足够简单。

# 18. Early Adopter 原则

这是 PhotoName 商业策略中非常重要的一条：

> **已经购买 Pro 的用户，不因为未来涨价再次付费。**

例如：

```text
2026

User A
$9.99
购买 PhotoName Pro
```

之后：

```text
2027

PhotoName Pro
$19.99
```

User A：

```text
仍然拥有 Pro
无需补 $10
```

新用户：

```text
购买价格 $19.99
```

原因：

早期用户承担了：

* 更少的功能；
* 更多潜在 Bug；
* 帮助产品验证市场；
* 提供早期反馈；

较低价格实际上是：

> **Early Adopter Discount**

# 19. Pro Product ID 不随涨价变化

正常情况下始终保留：

```text
com.photoname.pro
```

例如：

```text
PhotoName 1.0
Pro = $9.99

PhotoName 1.5
Pro = $14.99

PhotoName 2.0
Pro = $19.99
```

Product ID：

```text
com.photoname.pro
```

始终不变。

只是调整 App Store Connect 中的新用户售价。

这样：

```text
已有 Pro 用户
     ↓
仍然拥有 entitlement
```

不会因为涨价受到影响。

例如 PhotoName 已经成熟后，新开发：


> PhotoName Ingest Pack

> 永远保留。

# 21. StoreKit 技术架构

商业化模块必须与核心业务解耦。

推荐结构：

```text
StoreKit
   ↓
PurchaseManager
   ↓
EntitlementManager
   ↓
FeatureGate
   ↓
Application Features
```

---

# 22. PurchaseManager

职责：

```text
加载 App Store Product

发起 Purchase

监听 Transaction Update

Restore Purchase

获取当前 Entitlement

处理 Verified Transaction

处理 Revoked / Refunded Transaction
```

业务代码不能直接调用 StoreKit。

所有 StoreKit 操作统一封装在：

```text
PurchaseManager
```

---

# 23. EntitlementManager

`EntitlementManager` 不关心具体 StoreKit API。

只负责维护：

```text
enum Entitlement {
    case pro
}
```

以及类似：

```text
isPro
```

状态。

数据来源：

```text
PurchaseManager
```

---

# 24. FeatureGate

业务层不要到处出现：

```text
if isPro
```

建议增加统一的：

```text
FeatureGate
```

例如逻辑上：

```text
FeatureGate.canProcess(assetCount)
```

或者：

```text
FeatureGate.isAvailable(.customTemplate)
```

FeatureGate 根据：

```text
Entitlement
```

决定功能可用状态。

---

```text
PhotoName/
```


# 26. Domain 与商业化模块的边界

错误设计：

```text
RenameEngine.rename() {

    if !StoreKit.isPurchased {
        return
    }

}
```

这样会让核心业务和 StoreKit 强耦合。

正确关系：

```text
UI / UseCase
     ↓
FeatureGate
     ↓
是否允许处理 3000 Assets？
     ↓
YES
     ↓
RenameEngine
```

RenameEngine 本身：

> 不应该知道用户是否付费。

它只负责正确执行 Rename。

# 28. Entitlement Source of Truth

本地可以缓存：

```text
isPro = true
```

用于：

* 快速启动；
* UI 状态；
* 减少启动等待。

但是：

> 本地缓存不是最终授权来源。

真正 Source of Truth 应该是：

```text
StoreKit Transaction Entitlement
```

因此结构类似：

```text
App Launch
   ↓
读取 Local Cache
   ↓
快速显示 UI
   ↓
StoreKit Refresh
   ↓
更新 Entitlement
```

---

# 29. 不自行实现 License Key

不增加：

```text
XXXX-XXXX-XXXX-XXXX
```

这种 License。

也不做：

```text
邮箱 + License
```

原因：

* 需要 Server；
* 需要账号绑定；
* 需要 License 数据库；
* 需要设备限制；
* 需要迁移机制；
* 增加客服成本。

只要 PhotoName 主要通过 App Store 销售：

> Apple Account 就是用户的购买身份。

---

# 30. Restore Purchase

设置页必须提供：

```text
Restore Purchases
```

典型情况：

```text
用户购买 PhotoName Pro

↓

换了一台 Mac

↓

重新安装 PhotoName

↓

相同 Apple Account

↓

Restore Purchase

↓

Pro 恢复
```

整个过程无需 PhotoName Server。

---

# 31. Refund / Revocation

授权状态不能简单理解成：

```text
买过一次 = 永远 true
```

StoreKit 返回的有效 Entitlement 才代表当前状态。

如果交易发生：

```text
Refund

Revocation
```

EntitlementManager 应重新计算：

```text
isPro
```

避免自己永久缓存一个：

```text
true
```

---

# 32. 离线状态

PhotoName 必须允许已经验证过的 Pro 用户在没有网络时：

> 正常使用本地摄影功能。

不能因为：

```text
No Network
```

就禁止：

```text
Rename
Preflight
Undo
```

StoreKit / 本地 entitlement cache 应支持合理的离线体验。

购买和主动恢复购买则可能需要网络。

---

# 33. Paywall 原则

Paywall 应该简单。

例如：

```text
PhotoName Pro

Unlimited photography workflow.

✓ Unlimited assets
✓ Custom templates
✓ Advanced naming
✓ Professional workflows

$9.99

Lifetime Purchase
```

明确强调：

```text
One-time purchase

No subscription
```

不要使用：

* 倒计时；
* 强制弹窗；
* 多层套餐；
* 虚假折扣；
* 难以关闭的 Paywall。

PhotoName 的目标用户更偏专业工具用户。

商业体验本身也应该：

> Simple / Trustworthy。

# 39. 商业化红线

后续开发过程中不得违反以下原则。

## 不因为收费降低数据安全

任何安全功能必须免费。

---

## 不为了授权建设不必要服务器

优先使用 StoreKit。

---

## 不把 StoreKit 写进 Domain Core

购买逻辑与摄影处理逻辑必须解耦。

---

## 不频繁增加 SKU

默认维持：

```text
Free
Pro Lifetime
```

---

## 不损害老用户权益

购买时承诺的 Pro 功能：

> 不因为后续涨价失效。

---

## 不强推订阅

除非未来 PhotoName 出现真正持续产生服务器成本的服务。

# 41. 商业化策略总结

PhotoName 的商业化并不是建立一套复杂 SaaS。

而是：

> **让 Apple 管支付，让 PhotoName 专心处理照片。**

第一阶段：

```text
Free
+
Pro Lifetime
```

随着产品能力增强：

```text
$9.99
 ↓
$14.99
 ↓
$19.99
 ↓
$24.99+
```

涨价只影响：

> **未来的新用户。**

已经购买的 Early Adopter：

> 永久保持已有 Pro 权益。

只有未来出现真正独立、产品级的新能力，才考虑新增一次性 IAP。

最终保持整个 PhotoName：

```text
No Account

No Login

No Own Server

No License Server

No Subscription

No Photo Upload

Local Processing

StoreKit Purchase

Lifetime Pro
```

这不仅是一种技术架构选择，也是 PhotoName 产品定位的一部分：

> **Simple software, local photos, one-time purchase.**
