# PhotoName 项目文档

记录 PhotoName 的设计决策与开发过程。所有文档随代码一起维护，改了行为就同步改文档。

## 目录结构

| 目录 | 放什么 | 何时写 |
|------|--------|--------|
| [10-宪章](10-宪章/) | 编码规范、commit 规范等长期不变的约定 | 项目初期一次写好，偶尔修订 |
| [20-产品PRD](20-产品PRD/) | **项目的事实来源**：产品规格（PRD）、商业化策略、[产品介绍-外发版](20-产品PRD/产品介绍-外发版.md) | 需求/商业策略变更时修订 |
| [30-架构设计](30-架构设计/) | 分期路线图、架构总览、各模块设计 | 每开始一个新模块前先写设计 |
| [40-踩坑记录](40-踩坑记录/) | Swift 6 并发、StoreKit、XcodeGen 等踩过的坑 | 踩到就记，含解决方案 |

## 核心文档（阅读顺序）

1. [产品说明文档](20-产品PRD/产品说明文档.md) — 产品定位、功能规格（F-01~F-12）、MVP 分期（Phase 0-7）
2. [产品商业化文档](20-产品PRD/产品商业化文档.md) — Free/Pro 边界、买断制 StoreKit 设计、商业化红线
3. [分期路线图](30-架构设计/01-分期路线图.md) — 开发进度与各阶段任务，以 PRD §19 为准

## 约定

- 每个目录用 `NN-前缀` 编号，排序即阅读顺序
- 设计文档命名：`NN-主题.md`，编号代表写作/阅读顺序
- 文档过时比没有文档更糟：发现与现实不符，当场改或当场删
